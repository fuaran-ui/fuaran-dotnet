# Phase 12.I – i18n + a11y as first-class binding kinds

**Shipped:** 2026-05-26. Phase file: `roadmap/phases/12-I-fern-i18n-a11y-first-class-bindings.md`.

**Stability impact:** Additive – pre-1.0 minor bump on every Fuaran package whose surface area extends (`Fuaran.UI`, `Fuaran.UI.Renderer`, `Fuaran.UI.Ops`, `Fuaran.UI.AiTools`, `Fuaran.UI.OpStream.Abstractions`, `Fuaran.UI.Validator`). No source-level breakage for consumer code that constructs Nodes via the smart constructors. Consumers that pattern-match on `Binding<'T>` or `BindingResolver.Resolution<'T>` exhaustively will see `FS0025` warnings until they add the new cases – same pattern as past additive DU bumps.

## What changes

Two additive surfaces:

1. **`Binding.I18n` DU case** – `Binding.I18n of key: string * args: Map<string, Binding<obj>> option`. Resolves through `BindingSources.I18nResolver`, an `II18nResolver` interface apps wire to their preferred i18n backend (a platform i18n service, gettext, ICU, simple string-template). The default resolver is a passthrough that returns `[i18n:<key>]` so missing translations stay loud in dev. Resolution returns a new `BindingResolver.Resolution<'T>.I18nUnresolved key` case when the resolver reports a miss.

2. **`Accessibility` trait on `Node<'Msg>`** – a new optional record field `Accessibility: Accessibility option` carrying `Label` / `LabelledBy` / `DescribedBy` / `Role` / `LiveRegion` / `Hidden`. Per-component sensible defaults live in `Defaults.Accessibility.X`; smart constructors (`Fuaran.button`, `Fuaran.callout`, etc.) populate them so authors don't author ARIA metadata for the common cases. The renderer projects this into HTML `aria-*` / `role` / `aria-live` / `aria-hidden` attributes.

Plus three knock-on additions:

3. **`Fuaran.UI.Validator` two new checks** – `FUARAN040` Error (interactive `Fuaran.button` with `Accessibility = None` and no derivable Label) and `FUARAN041` Warning (high-tone `Fuaran.callout` with `Accessibility = None` losing the announcement).
4. **`Fuaran.UI.AiTools.BindingSource.I18n`** – new discriminator case for AI probes / introspection.
5. **`Fuaran.UI.OpStream.Abstractions.CanonicalJson`** – encoders for `Binding.I18n` + `Accessibility` so canonical JSON snapshots round-trip the new surface.

## Source-level diff to apply

### 1. `Fuaran.UI/Types.fs` – additive

Three new types + an interface + one DU case + one record field:

```fsharp
// Before Node<'Msg>:
[<RequireQualifiedAccess>]
type AriaRole =
    | Button | Link | Dialog | Alert | Status | Banner
    | Navigation | Main | Form | Region | Heading
    | Progressbar | Tab | Tablist | Tabpanel
    | Custom of role: string

[<RequireQualifiedAccess>]
type LiveRegionKind = Polite | Assertive | Off

type II18nResolver =
    abstract member Resolve: key: string * args: Map<string, obj> option -> string

// Extended Node<'Msg>:
type Node<'Msg> =
    { Id: NodeId
      Kind: NodeKind<'Msg>
      State: StateBehaviour<'Msg>
      Style: SemanticStyle
      Accessibility: Accessibility option }   // NEW

and Accessibility =
    { Label: Binding<string> option
      LabelledBy: NodeId option
      DescribedBy: NodeId option
      Role: AriaRole option
      LiveRegion: LiveRegionKind option
      Hidden: Binding<bool> option }

// Extended Binding<'T>:
and [<RequireQualifiedAccess>] Binding<'T> =
    | Static of 'T
    | Query of name: string * accessor: (obj -> 'T)
    | Filter of name: string
    | Selection of nodeId: NodeId * accessor: (obj -> 'T)
    | State of key: string * defaultValue: 'T
    | Computed of (BindingContext -> 'T)
    | I18n of key: string * args: Map<string, Binding<obj>> option   // NEW
```

### 2. `Fuaran.UI/Defaults.fs` – new `Defaults.Accessibility.X` module

Per-component defaults; see `Fuaran/src/Fuaran.UI/Defaults.fs` for the full set. Highlights:

- `Defaults.Accessibility.button = Some { ...; Role = Some AriaRole.Button }`
- `Defaults.Accessibility.callout = Some { ...; Role = Some AriaRole.Alert; LiveRegion = Some LiveRegionKind.Assertive }`
- `Defaults.Accessibility.progress = Some { ...; Role = Some AriaRole.Progressbar; LiveRegion = Some LiveRegionKind.Polite }`
- `Defaults.Accessibility.dashboard = Some { ...; Role = Some AriaRole.Main }`
- `Defaults.Accessibility.none = None` – decorative shapes (Stack, Spacer, Heading, Skeleton, Sparkline) inherit no ARIA emission.

### 3. `Fuaran.UI/Fuaran.fs` – `buildNode` extended; `Node.withAccessibility` added

The private `buildNode` helper now takes an additional `accessibility: Accessibility option` argument. Each smart constructor passes the matching `Defaults.Accessibility.X` (or `Defaults.Accessibility.none` for decorative shapes). Authors override per-Node via:

```fsharp
let node =
    Fuaran.button "submit" { Defaults.button<Msg> with Label = TextSource.Literal "Submit" }
    |> Node.withAccessibility (Some { Defaults.Accessibility.empty with LiveRegion = Some LiveRegionKind.Polite })
```

### 4. `Fuaran.UI.Renderer/BindingResolver.fs` – `I18nResolver` field + `I18nUnresolved` case

```fsharp
// Extended BindingSources:
type BindingSources =
    { ...
      I18n: Map<string, string>             // existing (TextSource.I18n backward compat)
      I18nResolver: II18nResolver }         // NEW — Binding.I18n resolution

// Extended Resolution:
type Resolution<'T> =
    | Resolved of 'T
    | NotResolved
    | Errored of message: string
    | I18nUnresolved of key: string         // NEW

// New helpers:
let passthroughI18nResolver: II18nResolver = ...
let makeI18nResolver (catalog: Map<string, string>) : II18nResolver = ...
```

`BindingResolver.empty` now wires `I18nResolver = passthroughI18nResolver`. Apps replace the field with their own `II18nResolver` instance (e.g. `BindingResolver.makeI18nResolver myCatalog`).

### 5. `Fuaran.UI.Renderer/Render.fs` – accessibility attribute emission

The top-level `render` function now reads `node.Accessibility` and emits matching `aria-*` / `role` / `aria-live` / `aria-hidden` attributes on the outer `<div>`. Implementation factored through `accessibilityAttributes : BindingSources -> Accessibility option -> (string * string) list` (public so `AccessibilityTests.fs` can pin the projection without a Feliz round-trip).

`aria-labelledby` / `aria-describedby` resolve `NodeId` references to the target Node's stable HTML `id` attribute – the same string the renderer emits as `prop.id`.

## Rollback

The change is wholly additive. To revert in a forked clone:

1. Revert the commit that introduced these files. Git history pins both commits separately:
   - Commit 1: Types/Defaults/Resolver/Render additive surface + tests.
   - Commit 2: Validator rules + this migration doc.
2. Re-run `dotnet fantomas . && dotnet build Fuaran.sln`.

Consumer apps that adopted `Binding.I18n` or `Node.Accessibility` will fail to compile post-revert; remove those references first.

## v1 limitations

- **`Binding.I18n` is semantically constrained to `Binding<string>`.** The DU shape allows any `'T`, but the resolver always returns a string; using `Binding.I18n` on a non-string `Binding<'T>` throws at resolution time with a typed error. Same shape as `Binding.Query`'s accessor cast.
- **`accessibilityAttributes` projection only covers the six fields above.** There is no structural-Label `aria-label` fallback: when `Accessibility.Label` is None the projection emits no `aria-label`, and the structural label (e.g. `ButtonSpec.Label`) names the element by becoming its text content — the browser's accessible-name computation falls through `aria-label` → `aria-labelledby` → text content.
- **Validator FUARAN040 / FUARAN041 only detect explicit `Accessibility = None`.** Inherited defaults (the common path) don't fire. Deeper inspection (e.g. `Accessibility = Some { ... LiveRegion = None }`) needs a richer AST walker, deferred to a follow-on.
- **JSON round-trip is encode-only.** `CanonicalJson.fs` ships the encoder side for both new shapes; a matching `CanonicalJsonDecoder` extension lands when the downstream AI consumer needs to ingest persisted i18n snapshots.
- **Catalog (Phase 12.S) integration is not in this phase.** When the Catalog ships its faceted control plane, an `i18n` axis + an `a11y-audit` view become subsequent additions.
